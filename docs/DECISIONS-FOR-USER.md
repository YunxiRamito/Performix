## A0（偏差说明）：我动了 `PreySense.Core` 一个文件，需要你追认

- **原定约束**：迁移期「硬件层 `PreySense.Core` 与 `IHardwareService` 一行不改」。
- **实际发生**：修风扇转速串值时，改了 `app\Fork\PreySense.Core\Hardware\WmiController.cs` 三处 + `Diagnostics\AcerSensorProbe.cs` 两行注释 + 新增测试 `FanChannelSeparationTests.cs`（6 条）。
- **改了什么**：只把 WMI 回退/诊断路径上的 `RoundToNearest100` 换成直通 `FanRpmFromSensorReading`（`-1` 哨兵保留）。原来它把 4054 和 4109 都量化成 4100，看起来像「两个风扇被解成同一个值」。
- **没改什么**（逐项核对过）：`Hardware\` 与 `Rgb\` 下**协议常量、帧结构、cmd 号**一行未动（`0x00410009/0x00820009/0x00C30009`、cmd 15/16/17/30/32/33、`duty<<8|fanId`、1=CPU/4=GPU、11 字节帧、传感器 id 表全部原样）。
- **证据**：构建 0/0；单测 584 通过 / 0 失败（新增 6 条，未弱化任何旧断言）；探针 WMI 行从 `4100/4100` 变成 `4109/4054`。
- **需要你选**：
  1. **追认保留**（我建议这条）——解码层 bug，不碰协议，留着只有好处；
  2. **回滚**——还原那三处，风扇转速会重新被量化到 100，UI 上两扇可能显示同值；
  3. 追认但把改动挪到「前端解码层」而不是 Core（工作量大一些，需要新加一层适配）。

## A. 必须先定，再往下做才有意义

### A1 二级页窗口高度的封顶值：520 还是 640 DIP？
- 现状：实现按 **520 DIP 整窗高**（标题栏 40 + 内容 480），内容超了页内滚动。
- 起因：Claude 施工单写 640，但壳改造那轮已经照「≤520」验收并出图，`polish` 选择不推翻已验收交付，保留了 520。
- 选项：520（更轻、更像浮窗） / 640（一屏看到更多，少滚动） / 按页给不同上限（设置 480、调校 640、灯效 640）
- 建议：**520 保持**。320 窄窗再高就像面板了，滚轮翻页体验也不差。

### A2 「狂暴模式」到底要写什么硬件？
- 现状：现在点「狂暴」= 切 Acer 模式 0x05 + 应用该模式保存的风扇曲线/CPU 调度（和 WPF 版一致）。**没有**额外「风扇拉满 + 调度激进 + 电源拉满」的强制预设。
- 你原话：「狂暴对应原版 turbo 键，风扇拉满，性能调度激进，电源选项拉满。剩下参考 TS 的配置文件」。
- TS（ThrottleStop）现值我读到了：4 个 profile「高性能 / 增强 / 普通 / 节能」，`Options=0x01102980`（节能单开 `0x01102981`），`DutyCycle` 16/16/16/11，`EIST=14`，`SST EPP` 相关 `EnPerfPref` 0/32/84/204。**但 TS 里大头的降压/功耗墙走 MSR，本机 BIOS 锁死**（`Agent.md` 红线 §3.1），我们只能落地 powercfg 那十项 + 风扇 + Acer 模式。
- 需要你定：
  1. 「狂暴」是否要在切模式时**强制**写入一组调度值（最大处理器状态 100 / Boost Aggressive / EPP 0 / 核心停泊 100/100 / 风扇 Max）？还是只切 Acer 模式、其余沿用该模式已保存的值？
  2. 如果强制写，是**每次切狂暴都写**（会覆盖你手动调的值），还是只在预设算法里作为默认值？
- 建议：**强制写一组显式预设 + 界面上给一行「狂暴预设将覆盖当前 CPU 调度」的提示**，因为「狂暴」这个名字承诺的就是激进。

### A3 狂暴键的语义
- 现状：按一次 = **切到狂暴**。官方 Predator Sense 的语义是「狂暴 ↔ 上一个模式」来回切。
- 选项：置狂暴（现在） / 来回切（官方行为）
- 建议：**来回切**，与官方一致，用户不会因为误触永久停在狂暴。
- 另：这个键还没在真机上确认过 ACPI 字节（见 D1），实现是「先打日志、认 `07 04`」。

## B. 迁移收尾相关

### B1 开机自启指向哪一版？
- 现状：计划任务名 `PreySense`，注册的是「**最后一次在哪个 exe 里开关过开机启动**」。本机现在**没有**自启任务。`edition.txt` 默认 `winui`。
- 需要你定：自启跟着 `edition.txt` 走（我可以在设置里做「切版时自动重注册」），还是永远指向 `app\dist-winui`？
- 建议：跟着 `edition.txt`，并在设置页加一行「开机启动：PredeX (WinUI) / Predex (WPF)」显示当前指向。

### B2 两版共存的互斥
- 现状：WPF 版 mutex `PreySenseApp_Unique_System_Mutex_999`、WinUI 版 `PredexWinUI_Unique_Mutex_1234`，**两版能同时跑** → 抢风扇/EC、配置互相覆盖（后写赢）。
- 选项：① 统一 mutex 名（一版跑时另一版起不来）② 保持现状，只在 `Run-GUI.ps1` 里给警告（现在就是这样）
- 建议：**①统一**。`Agent.md` 说不要改 mutex 名，但那条的本意是「别让升级丢单实例能力」，新增一个**跨版互斥**（共享同一个名字）比改名更安全——这话要你确认，因为踩红线。

### B3 两份配置
- 现状：`preysense.json` 跟 exe 同目录 → `app\dist` 与 `app\dist-winui` **各一份**（schema 完全兼容）。`Rollback-ToWpf.ps1 -SyncConfig` 可以搬。
- 建议：接受两份独立；切版时用 `-SyncConfig` 搬一次。要不要做「自动同步」由你定（自动同步有覆盖风险）。

### B4 WPF 版还留多久
- 现状：WPF 版完全没动、可构建、可回滚；`Compat/WpfShims.cs` 是 WinUI 侧为了链接 WPF ViewModel 而存在的垫片，**删不掉**（除非改 WPF 版把 `Dispatcher`/`Application` 抽象掉）。
- 建议：**WPF 版冻结当回滚路径**，至少保留到 WinUI 版连续用一周没翻车。
